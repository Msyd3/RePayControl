# RePayControl

> تحديث 11 نوفمبر 2026: الواجهة الحالية صفحة واحدة بدون قائمة جانبية أو هيدر، بتصدير PDF وقائمة مستخدمين مفصلة. تعتمد الإيرادات على 1.15 ريال لكل سحب بنكي ناجح. [المواصفات الحالية وعقد البيانات](docs/CONTROL-V2.md) تتقدم على وصف الواجهة والمقاييس القديم أدناه. لم تُربط مصادر الإنتاج بعد.

مركز قياس مستقل يجمع رؤية منتجات RePay الثلاثة. الواجهة عربية، بالأسود والأبيض وتدرجاتهما، بخط تجارب الأصلي من مشروع المحفظة، ومتجاوبة مع الجوال والكمبيوتر.

هذا تسليم **جاهز للتشغيل والنشر لاحقًا** بناءً على اختيار المستخدم. لم يُنشر المشروع، ولم تُعدّل المستودعات الأصلية أو الاستضافات. لا توجد بيانات تجريبية في قاعدة البيانات، ولا مفاتيح إنتاج في الملفات. صور المعاينة تعرض الحالة الحقيقية قبل توصيل المصادر.

## ما يتضمنه

- لوحة خاصة بكلمة مرور، وفلاتر المنتج والفترة، وتحديث دوري وتصدير CSV.
- زيارات وصفحات وزوار وجلسات ونشطون الآن وزوار عائدون وارتداد ووقت تفاعل.
- نقرات الأزرار والروابط، الروابط الخارجية، التنزيلات، النماذج وعمق التمرير.
- مصادر الزيارات، وسوم الحملات UTM، الأجهزة والمتصفحات.
- مسارات تحويل متسلسلة، مع فصل محاولات الواجهة عن نتائج الخادم المؤكدة.
- مستخدمون معرّفون بمعرّفات مجهّلة، وطلبات تواصل محفوظة ودفعات موثقة وقيمتها بالريال.
- أداء LCP وCLS وFCP وTTFB، وأخطاء الواجهة وحالات API ومدة الاستجابة.
- قارئ لإحصاءات RePay POC الحالية، وقارئ لتواريخ Google Sheets دون أسماء العملاء.
- ملفات تثبيت للواجهتين، وربط خادم نموذج الأعمال وقياس رسائل واتساب.
- قاعدة SQLite دائمة، ومنع تكرار الأحداث، واحتفاظ افتراضي 90 يومًا، واختبارات.

بعض المقاييس تحتاج مصدرها الخلفي قبل ظهورها. لا توجد وسيلة لاستخراج أعداد الزوار السابقة من كود GitHub، ولا لاستنتاج الدفعات الفعلية من صفحة نجاح. التفاصيل في [تقرير المصادر](docs/SOURCES.md) و[تعريف المقاييس](docs/METRICS.md).

## تشغيل محلي سريع

المتطلب الوحيد: **Node.js 24 أو أحدث**. لا يحتاج المشروع إلى npm install أو خدمات تحليل مدفوعة.

من مجلد المشروع:

```sh
node src/setup.mjs
npm start
```

افتح `http://127.0.0.1:4317`. اقرأ قيمة `ADMIN_PASSWORD` محليًا من ملف `.env` الذي أنشأه أمر الإعداد لتسجيل الدخول. الملف خاص بجهازك ومُستثنى من Git؛ لا تشاركه ولا تضعه في ZIP. يعين الإعداد المحلي وضع development حتى تعمل الجلسة على localhost. سيمنع الإعداد إعادة الكتابة فوق ملف أسرار موجود.

## النشر المستقل

التفاصيل في [دليل النشر](docs/DEPLOYMENT.md).

1. ارفع **هذا المجلد وحده** إلى مستودع جديد باسم `RePayControl` أو إلى الاستضافة التي تختارها.
2. استخدم Dockerfile أو Node 24 مع أمر بدء `node src/server.mjs`.
3. عيّن `NODE_ENV=production` وثلاثة أسرار مستقلة بطول 32 حرفًا على الأقل: `ADMIN_PASSWORD` و`SESSION_SECRET` و`SERVER_INGEST_KEY`.
4. اربط مجلد `DATA_DIR` بوحدة تخزين دائمة، ورابط HTTPS، مثل `https://control.YOUR_DOMAIN`.
5. عيّن النطاقات الفعلية للمشاريع في `WALLET_ORIGINS` و`BUSINESS_ORIGINS` و`POC_ORIGINS`.
6. ثبّت ملفات الربط الموضحة أدناه، ثم اختبر استقبال الأحداث.

لا يصلح GitHub Pages أو أي استضافة ملفات ثابتة وحدها لتشغيل خادم القياس. تشغيل نسخة واحدة مع قرص محلي دائم هو نمط هذا الإصدار. التوسع إلى عدة نسخ يحتاج قاعدة مشتركة وتحديد معدل موزع.

## ربط المشاريع الثلاثة

لا يعدّل المثبّت شيئًا إلا عند إضافة `--apply`. يُفضّل تشغيله داخل فرع منفصل من كل مشروع ومراجعة الفروقات. استبدل المسارات والرابط بالقيم الفعلية:

```sh
node integrations/install.mjs wallet /path/to/RePay-Wallet --origin=https://control.YOUR_DOMAIN
node integrations/install.mjs business /path/to/repay-for-business --origin=https://control.YOUR_DOMAIN
node integrations/install.mjs poc /path/to/RePay-POC --origin=https://control.YOUR_DOMAIN
```

بعد المراجعة، أعد كل أمر مع `--apply`. يرفض المثبّت إجراء تبديلات غير معروفة إذا تغيرت الملفات الأصلية.

### المحفظة

يضيف التتبّع إلى كل صفحات HTML ويضيف نطاق الاستقبال إلى `connect-src` في `_headers`. إذا كان مضيفك يضبط CSP بطريقته، أضف النطاق هناك أيضًا. الزيارات لا تُرسل قبل موافقة المستخدم. زر «تفضيلات القياس» يتيح سحب الموافقة.

الإصدار الموجود من المحفظة واجهة أمامية؛ خدمات الحسابات والدفع غير موجودة في مستودعها. أضف أحداث `otp_requested` و`otp_verified` و`login_verified` و`payment_succeeded` إلى خادمها الفعلي لاحقًا وفق [عقد الأحداث](docs/EVENTS.md). لا توضع مفاتيح الخادم في JavaScript.

### موقع الأعمال

المثبّت يضيف bootstrap التتبّع إلى React، ويضيف إرسال `lead_created` **بعد** نجاح الحفظ في Google Sheets.

- إعداد بناء الواجهة: `VITE_CONTROL_ORIGIN`.
- إعداد خادم الأعمال: `REPAY_CONTROL_ORIGIN` و`REPAY_CONTROL_SERVER_KEY`؛ القيمة الثانية تطابق `SERVER_INGEST_KEY` في RePayControl.
- ملفات `.env.control.example` المضافة مرجع للإعداد، ولا تُقرأ تلقائيًا من الاستضافة. انقل القيم إلى متغيرات الاستضافة ثم أعد البناء والنشر.
- يرسل SDK معرّف الجلسة مع `/api/leads` بعد الموافقة لربط مسار النموذج بنتيجته. يُرسل حدث حفظ الطلب من الخادم حتى دون موافقة قياس الواجهة، لكن دون هوية العميل أو معرّفات متصفحه.
- الاتصال الحالي بـGoogle Sheets داخل موقع الأعمال يستخدم موصل Replit؛ **لا تغيّره**. قارئ RePayControl المستقل اختياري ويستخدم حساب خدمة للقراءة فقط.

### مشروع واتساب

للإحصاءات الموجودة أصلًا، اضبط في **RePayControl**:

```text
POC_API_ORIGIN=https://repay-poc.onrender.com
POC_ANALYTICS_PASSWORD=<قيمة RePay__AnalyticsPassword في خادم POC>
```

لا يحتاج هذا القارئ إلى تعديل POC. يعرض إجماليات المستخدمين والمحادثات وطلبات التحويل، ولا يعرض قائمة الأسماء أو الهواتف.

المثبّت الاختياري يضيف `RePayControlClient.cs` إلى POC لاستقبال قياسات الرسائل الواردة وحالات الإرسال والتسليم والفشل بعد معالجة Webhook، مع إزالة هويات الأشخاص قبل الإرسال. اضبط `RePayControl__Origin` و`RePayControl__ServerKey` على مضيف POC. إرسال القياس best effort ولا يحوّل فشله إلى فشل لحفظ طلب التواصل أو لمعالجة Webhook.

الخطاف لا يسجل الطلبات والمبالغ أو تكلفة الذكاء الاصطناعي تلقائيًا، ولا يدّعي قياس دفع مؤكد. الأحداث الإضافية مهيأة في العقد وتحتاج وضعها عند الانتقالات الصحيحة في خدماتها.

## Google Sheets الاختياري

أنشئ حساب خدمة، وامنحه قراءة الجدول المطلوب فقط، ثم اضبط `GOOGLE_CLIENT_EMAIL` و`GOOGLE_PRIVATE_KEY` و`GOOGLE_SPREADSHEET_ID` و`GOOGLE_SHEET_TITLE` في استضافة RePayControl. حافظ على المفتاح خارج المصدر. القارئ يطلب النطاق `A2:A100001`: يفترض أن الصف الأول عنوان وأن العمود A يحتوي تاريخ ISO كما يكتبه خادم الأعمال. إذا تغير ترتيب الجدول عدّل النطاق قبل التفعيل. لا تُقرأ الأعمدة التي تحتوي الأسماء والهواتف والبريد.

## التحقق

```sh
npm run check

```

اجتاز المشروع 14 اختبارًا وظيفيًا، وجرى التحقق من جميع أقسام الواجهة عند 1440 و390 بكسل. بعد تطبيق ربط المحفظة على نسخة فحص منفصلة نجحت اختبارات المحفظة الأصلية الـ16 وفحص ملفاتها وبناء الإنتاج. اجتازت إضافات TypeScript فحص الصياغة. لم تُبنَ إضافات C# أو مشروع React كاملًا هنا لعدم توفر .NET وبيئة تبعيات المشروع الأصلي؛ شغّل فحوص مشروعيهما قبل دمج تغييرات الربط. لم يُختبر اتصال إنتاج لأن الربط مؤجل حسب الطلب.

راجع [نتائج التحقق](docs/VALIDATION.md) و[خطوات اختبار الربط](docs/DEPLOYMENT.md#اختبار-بعد-الربط).

## الملفات المهمة

| المسار | المحتوى |
|---|---|
| `public/` | الواجهة وخط تجارب وSDK التتبّع |
| `src/server.mjs` | خادم الويب وحماية الإدارة واستقبال الأحداث |
| `src/store.mjs` | التحقق من الأحداث والتخزين والتجميع |
| `src/connectors.mjs` | قراءة إحصاءات POC وGoogle Sheets |
| `integrations/` | المثبّت وربط React وExpress وC# والموافقة |
| `docs/` | النشر وتعريف المقاييس وعقد الأحداث وتقرير المصادر |
| `tests/` | اختبارات القياس والحماية وSDK |
| `previews/` | صور واجهة قبل توصيل البيانات |

خط تجارب مأخوذ من أصول المحفظة، مع إبقاء ملف ترخيصه بجانبه في `public/fonts/`.

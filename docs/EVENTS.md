# عقد أحداث RePayControl

## مبدأ الثقة

لا يرسل المتصفح نتائج تجارية موثوقة. `/api/events` يقبل سلوك المتصفح فقط. `/api/server-events` يقبل أسماء أحداث الخادم فقط ويتطلب `Authorization: Bearer SERVER_INGEST_KEY`. لا تنقل المفتاح إلى React أو HTML أو التطبيق المحمول أو SDK.

الحدث المكرر لا يُحتسب مرتين بناءً على `(project, trusted, id)`. مصدر المتصفح منفصل عن الخادم حتى لا تحجب نقرة تحمل معرّفًا مماثلًا حدثًا ماليًا موثوقًا. تُسجّل الأحداث بتوقيت الاستلام من الخادم؛ لا يُعتمد على توقيت العميل ولا يدعم هذا الإصدار الاستيراد التاريخي للأحداث.

## مثال خادم

بعد تحقق خادم الدفع من توقيع webhook ومن أن العملية سُددت فعليًا:

```js
await fetch(new URL('/api/server-events', process.env.REPAY_CONTROL_ORIGIN), {
  method: 'POST',
  redirect: 'error',
  signal: AbortSignal.timeout(1500),
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${process.env.REPAY_CONTROL_SERVER_KEY}`,
  },
  body: JSON.stringify({events: [{
    id: providerEvent.id, // نفس المعرف عند إعادة المحاولة
    project: 'wallet',
    name: 'payment_succeeded',
    userId: internalOpaqueUserId, // لا ترسل الاسم أو الهاتف أو البريد
    session: savedControlSession, // حُفظت عند بدء العملية، إن توفرت موافقة القياس
    visitor: savedControlVisitor,
    path: '/summary',
    amountMinor: verifiedAmountMinor,
    currency: 'SAR',
  }]}),
});
```

لا تضع الخطاف في زر الدفع أو صفحة النجاح. اربط جلسة الواجهة بالعملية عند إنشائها ثم استرجعها من خادمك عند وصول webhook؛ لا تتوقع وجود Cookie المتصفح لدى مزوّد الدفع. لا تعتمد على session لإثبات المستخدم، فهي للارتباط التحليلي فقط.

إذا كان معرّف المزوّد يحوي محارف غير مسموحة أو يزيد على 120 حرفًا، حوّله إلى HMAC ثابت محليًا. نجاح إدخال `payment_succeeded` يتطلب `currency: SAR` ومبلغًا صحيحًا بالهللات بين 0 و100,000,000,000؛ القيم الأخرى تُرفض ولا تتحول إلى إيراد.

## الحقول

| الحقل | المعنى |
|---|---|
| `id` | معرف حدث ثابت وفريد داخل المصدر والمشروع، 1–120 محرفًا من الحروف الإنجليزية والأرقام و`_.:-` |
| `project` | `wallet` أو `business` أو `poc` |
| `name` | اسم مسموح من الجدول أدناه |
| `session`, `visitor` | معرفات SDK العشوائية عند وجود موافقة؛ لا ترسل الهاتف أو البريد |
| `userId` | خادم فقط؛ معرف حساب داخلي مبهم، يخزنه RePayControl كـHMAC مفصول حسب المشروع |
| `path` | مسار معروف؛ تُحذف معاملات الرابط ومعرفات العمليات، والبقية `/other` |
| `target` | معرف تطوير ثابت للزر أو النموذج؛ لا ترسل نصًا كتبه المستخدم |
| `metric`, `value` | اسم مقياس الأداء وقيمته؛ لا تُستخدم لأي محتوى حر |
| `duration` | مدة بالميلي ثانية |
| `status` | حالة HTTP من 0 إلى 599؛ 0 لفشل الشبكة |
| `source`, `medium`, `campaign` | قيم UTM قصيرة من الحروف المسموحة؛ تُرفض قيم تحوي 7 أرقام متتابعة |
| `amountMinor`, `currency` | نجاح دفع موثوق فقط؛ هللات SAR |

الحد 40 حدثًا و64KB لكل طلب. معرفات الجلسات والحملات والأهداف تُفرّغ إذا لم تجتز التحقق. الحقول غير المعروفة لا تُخزَّن. لا تُرسل أجسام الطلبات، أو قيم الحقول، أو عناوين الصور، أو محتوى الرسائل، أو stack traces.

## الأحداث المتاحة

| أحداث المتصفح الآلية | الغرض |
|---|---|
| `page_view` | فتح صفحة أو تغير مسار SPA |
| `click` | نقرة زر أو رابط |
| `outbound_click`, `download` | تصنيفات إضافية للنقرة نفسها؛ لا تجمعها مع click للحصول على عدد النقرات الفريد |
| `form_start`, `form_submit` | بدء نموذج ومحاولة إرساله، دون افتراض نجاحه |
| `scroll` | عتبات 25/50/75/100% |
| `engagement` | نبض وقت الصفحة المرئية مع تفاعل حديث |
| `performance` | LCP وCLS وFCP وTTFB حسب دعم المتصفح |
| `js_error` | تصنيف عام لخطأ واجهة أو Promise |
| `api_request` | طلب fetch إلى API على النطاق نفسه، حالته ومدته فقط |

| أحداث الخادم المسموحة | نقطة الإرسال الصحيحة |
|---|---|
| `user_registered` | بعد إنشاء الحساب فعليًا |
| `login_verified`, `otp_requested`, `otp_verified` | بعد نتيجة خدمة المصادقة المؤكدة |
| `checkout_started` | إنشاء جلسة دفع معتمدة |
| `payment_succeeded`, `payment_failed` | نتيجة دفع موثقة؛ لا من الواجهة |
| `transfer_requested`, `transfer_cancelled` | حفظ أو إلغاء طلب تحويل |
| `lead_created` | بعد حفظ طلب التواصل؛ مُضاف في ربط Express |
| `message_received`, `message_sent`, `message_delivered`, `message_failed` | Webhook واتساب الموثوق؛ مُضافة في ربط C# |
| `ai_request`, `ai_failure` | نتيجة استدعاء مزوّد الذكاء الاصطناعي |
| `webhook_received`, `webhook_failed` | استقبال/فشل معالجة موثّق في الخادم |
| `bank_account_added`, `profile_updated` | بعد حفظ التعديل ونجاح سياسة التحقق |

قبول اسم حدث في العقد لا يعني أنه مُرسل تلقائيًا. المثبّت يضيف `lead_created` وأحداث رسائل واتساب المذكورة فقط؛ باقي الأحداث تحتاج ربطًا داخل خدماتها الخلفية عند توفرها.

## الموافقة والقياس

SDK لا يبدأ حتى `RePayControl.grantConsent()` أو وجود موافقة سابقة. يحترم Do Not Track وGlobal Privacy Control. `revokeConsent()` يوقف القياس ويحذف معرفات الجهاز المخزنة محليًا؛ لا يحذف الأحداث السابقة تلقائيًا. زر تفضيلات القياس المرفق يسمح بالمراجعة والرفض. رسائل الأحداث تُرسل best effort مع طابور محدود في الذاكرة؛ قد تضيع عند إغلاق المتصفح أو تعطل الشبكة، لذلك ليست سجلًا ماليًا أو بديلًا لـoutbox موثوق.

خادم الأعمال يرسل عداد عملية الحفظ دون محتوى العميل حتى إذا رفض قياس الواجهة؛ لا يمرر visitor/session دون موافقة SDK. إن كانت سياسة منشأتك تتطلب ربط أحداث الخادم بالموافقة أيضًا فطبّق الشرط في `recordLeadCreated` قبل التفعيل. الموافقة هنا واجهة تقنية قابلة للمواءمة، وليست تفسيرًا قانونيًا للسياسة.

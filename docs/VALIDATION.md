# التحقق من التسليم

## ما اجتاز الفحص

- 14 اختبارًا لخادم RePayControl وSQLite وSDK: فصل الثقة، حماية الإدارة، CORS وربط النطاق بالمشروع، إزالة بيانات الرابط، منع التكرار، الدفعات الموثقة، ترتيب المسارات، الحذف حسب الاحتفاظ، بقاء البيانات عند إعادة الفتح، العائدون والارتداد، المئين 75، حماية بيانات POC، الموافقة وسحبها وDo Not Track، وتمرير معرف ارتباط دون OTP أو CSRF أو بيانات النموذج.
- تطبيق مثبّت الربط على نسخ مستقلة من المشاريع الثلاثة، دون تغيير المستودعات الأصلية.
- 16 اختبارًا أصليًا للمحفظة بعد تركيب الربط، وفحص 73 ملفًا من أصولها، وبناء الإنتاج.
- فحص صياغة JavaScript وTypeScript المضاف.
- تجربة دخول فعلية للوحة ومراجعة أقسامها التسعة على معاينة محلية بقاعدة مؤقتة فارغة.
- فحص الواجهة عند 1440px وعند 390px، والتحقق من تحميل خط تجارب وعدم وجود تمرير أفقي عام على الجوال.
- اختبار قائمة الجوال وتصفية المنتج والفترة، ومعالجة تبديل الفلاتر أثناء الطلبات المتزامنة.

## حدود التحقق

لم تُوصل مفاتيح الإنتاج أو Google Sheets أو حسابات الاستضافة؛ اختار المستخدم مشروعًا مستقلًا جاهزًا للنشر والربط لاحقًا. اختبارات قارئ POC تستخدم ردودًا معزولة ولا تدّعي اتصال الإنتاج.

لم تتوفر .NET أو Docker محليًا لتشغيل بناء C# أو صورة Docker. لم تُثبّت تبعيات المشروع الأصلي React/Express كاملة؛ فُحصت صياغة ملفات TypeScript المضافة، ويجب تشغيل typecheck/build واختبارات المشروع الأصلي عند دمج الربط. ملف Dockerfile يعتمد صورة Node 24 الرسمية؛ يحتاج اختباره على الاستضافة عند النشر.

لم تُنشأ موارد مدفوعة أو مستودعات GitHub جديدة، ولم تُعدّل استضافة أو قواعد بيانات أو ملفات في المستودعات الأصلية. كل تعديلات الدمج التي جرى التحقق منها كانت على نسخ فحص داخل مساحة العمل.

## تحديث 11 نوفمبر 2026

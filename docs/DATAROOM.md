# Data Room deployment
Do not merge/deploy until the separate backend is configured and tested. The frontend requires a live API with the same origin or the existing configured API origin. Only m@repay.sa can create folders or upload files, after email OTP (admin exempt from NDA). Other emails must be explicitly added to DATAROOM_INVITED_EMAILS (comma-separated). All invited users currently share read permissions. No wallet data is accessed by this API.
Configure independent private Tarout bucket and credentials: DATAROOM_BUCKET_ID, DATAROOM_ACCESS_KEY, DATAROOM_SECRET_KEY, DATAROOM_ENCRYPTION_KEY (random secret at least 32 characters, stable and backed up). Bucket must differ from existing TAROUT_BUCKET_ID. Set DATAROOM_EMAIL_API_KEY (Resend) and DATAROOM_FROM_EMAIL (verified sender). Never commit credentials. Maximum file size 10 MiB. Run one API instance: session and OTP state are in-memory and index mutations serialized only within one process. Restart invalidates sessions. Before production, test private bucket access, encryption, OTP delivery, denial of uninvited users and non-admin writes, NDA record persistence and file download. NDA v1 text is in public/dataroom/index.html; update the version on any revision. Scan uploaded files before sharing in production. No deletion or granular investor permissions in this iteration.

Investors accept once per NDA version after verified email. The server archives the exact displayed text and acceptance metadata as a PDF document under 03 Legal / NDA. That folder, its descendants and private files are excluded from investor list and download endpoints. This is electronic acceptance evidence, not a certified digital signature. Existing acceptances are not overwritten on repeated submissions.

PDF generation requires npm dependencies pdfkit and bidi-js. Verify Arabic rendering and acceptance metadata before production use.

# Data Room deployment
The frontend requires a live API with the same origin or the existing configured API origin. Only m@repay.sa can create folders or upload files, after entering the admin password (admin exempt from NDA). Other emails must have an active invitation in the Data Room. All invited users currently share read permissions. No wallet data is accessed by this API.
For the initial shared deployment, set `DATAROOM_STORAGE_MODE=shared` on RePay Control. The Data Room uses the existing private Tarout bucket and its attached `STORAGE_*` settings or existing `TAROUT_*` credentials, with all objects under `dataroom/`. Set a stable, independently generated `DATAROOM_ENCRYPTION_KEY` of at least 32 characters and back it up.

To move to a dedicated private bucket, pause writes, copy the complete `dataroom/` prefix to the new bucket, and verify that the copied objects match. Keep the same encryption key. Configure `DATAROOM_BUCKET_ID`, `DATAROOM_ACCESS_KEY`, and `DATAROOM_SECRET_KEY`, then set `DATAROOM_STORAGE_MODE=dedicated`. The dedicated bucket must differ from `TAROUT_BUCKET_ID`. Verify file downloads, invitations and NDA archives before resuming writes.

Set `DATAROOM_ADMIN_PASSWORD` in the hosting environment. It falls back to `ADMIN_PASSWORD` when unset. Invited investors enter their email address. This does not verify ownership of that address. Never commit credentials. Maximum file size 10 MiB. Run one API instance: session state are in-memory and index mutations serialized only within one process. Restart invalidates sessions. Before production, test private bucket access, encryption, admin password verification, denial of uninvited users and non-admin writes, NDA record persistence and file download. NDA v1 text is in public/dataroom/index.html; update the version on any revision. Scan uploaded files before sharing in production. Administrators can remove files and folders. The NDA archive folder and its parent are protected.

Investors accept once per NDA version using the invited email they entered. The server archives the exact displayed text and acceptance metadata as a PDF document under 03 Legal / NDA. That folder, its descendants and private files are excluded from investor list and download endpoints. This is electronic acceptance evidence, not a certified digital signature. Existing acceptances are not overwritten on repeated submissions.

PDF generation requires npm dependencies pdfkit and bidi-js. Verify Arabic rendering and acceptance metadata before production use.
